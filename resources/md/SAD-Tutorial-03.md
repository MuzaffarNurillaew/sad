What is Use Case?

Google

Wikipedia

“A use case is a specific, goal-oriented scenario
describing how a user (or "actor") interacts
with a system to achieve a particular outcome,
such as placing an order on a website or a
customer withdrawing cash from an ATM. In
software and systems engineering, use cases
define the system's functional requirements
from the user's perspective, helping to clarify
goals, plan development, and serve as a basis
for testing and documentation.”

“In both software and systems engineering,
a use case is a structured description of a
system’s behavior as it responds to
requests from external actors, aiming to
achieve a specific goal. The term is also
used outside software/systems engineering
to describe how something can be used.”

https://www.google.com/search?q=use+case

Use Case

As you can see, a “Use case” is just a table of text that
documents specific user-system interaction.

It has:
• Id
• Name
• Description,
• Actors
• Steps (happy path)
• Extensions (edge cases)
• Etc.

Let’s talk about each of these in detail.

Use case: Fields

Use Case Number

ID to uniquely represent your use case

Application*

Use Case Name

What system or application does this use case belongs to. For
example “Accounting” subsystem or “Mobile API”.

The name of your use case. Keep it short, but make sure it is
descriptive. For example: User registration, Editing blog post.

Use Case Description

Elaborate more on the name, in paragraph form.

Primary Actor

Who is the main actor that this use case represents?

Precondition*

What preconditions must be met before this use case can start? For
example: User registrations are enabled, post belongs to the user, etc.

Postconditions*

Trigger

Basic Flow

Extensions
(Alternate Flows)

What will be the guaranteed outcomes of this use case? For
example: User data inserted into the database, logged in and
redirected to the homepage.

What event triggers this use case? For example: User clicks on
register button in the registration form.

The basic flow should be the events of the use case when
everything is perfect; there are no errors, no exceptions. This is
the "happy path scenario". The exceptions will be handled in the
“Extensions (Alternate Flows)" section.

What is Use Case?

Google

Wikipedia

“A use case diagram is a high-level, visual
representation of a system's intended
functionality, showing the interactions
between users (called actors) and the various
functions (use cases) the system offers. It helps
define the system's scope and major features
from a user's perspective, serving as a
communication tool for understanding how the
system will be used without detailing its
internal operations.”

https://www.google.com/search?q=use+case+diagram

“A use case diagram is a graphical
depiction of a user's possible interactions
with a system. A use case diagram shows
various use cases and different types of
users the system has and will often be
accompanied by other types of diagrams as
well. The use cases are represented by
either circles or ellipses. The actors are
often shown as stick figures.”
