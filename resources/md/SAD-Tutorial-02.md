The role of Diagrams

• An image/diagram worths a thousand words.

• Diagrams simplify the complex information and makes it easier to understand.

• Stakeholders may not understand tech documentation but can quickly grasp a diagram.

• Reduce misunderstanding of the requirements (DFD, ERD, etc.).

• Help detecting redundancies, inconsistencies or missing information.

• Create a single communication language and increase communication efficiency.

• Makes communication across teams, organizations or time possible.

What is Data Flow Diagram?

A Data Flow Diagram is a visual representation of how data moves through a system.

It shows:

• Terminator – external entity that communicates with the system (people, other systems).

• Warehouse – warehouse used to store the data for later (file, database).

• Process – a process transforms inputs into outputs (system functions).

• Data flow – shows how data flow between from one part of the system to another.

DFD does not show any logic or implementation details — only the flow of information!

Levels of DFD

• Level 0 – High level view of the entire system as a single diagram.

Documents the whole system showing all external inputs/outputs and the
main system processes.

• Level 1 – Explains one or more process from Level 0 in more detail.

• Level 2, 3, etc. – Dive deeper into the processes.
